# 快捷键

> 对应 FR-10.6。键位一经发布不再变更；新增键位必须避开下表已占用组合。
>
> **实现状态（M1）**：`Alt+←/→/↑`、`Backspace`、`Ctrl+L`、`F5`、`Ctrl+R`、`Ctrl+Shift+1/2`、
> `Ctrl+Shift+D`、`Ctrl+,`、`Enter`、`F2`、`Delete`、`Shift+Delete`、`Ctrl+C/X/V`、`Ctrl+A`、
> `Ctrl+Shift+N`、`Ctrl+Shift+M`、`Ctrl+Shift+C`、`Alt+Enter`、菜单键（`VK_APPS`）已可用。
> `Ctrl+Shift+3`（大图标）**不绑定**：该视图决定不做，见 `docs/adr/0005-large-icon-view.md`。
>
> **实现状态（M2 / S3）**：标签页 10 条（`Ctrl+T`、`Ctrl+W`、`Ctrl+Shift+T`、`Ctrl+Tab`、
> `Ctrl+Shift+Tab`、`Ctrl+1…8`、`Ctrl+9`）已可用，全部走**窗口表**（标签集合属于窗口，
> 不属于某个窗格，见 `docs/pane-refactor.md` §7）。
>
> **实现方式**：键位表在 `Jianlan.App/Input/KeyBindings.cs`，采用**三入口**：
>
> 1. `Ctrl + ,` 单独走**系统热键**：窗口激活时 `RegisterHotKey`，失活立即注销，
>    命中时收到 `WM_HOTKEY` 打开设置。验证过程见下方"为什么 Ctrl+, 要特殊处理"。
> 2. 主入口是窗口消息 `WM_KEYDOWN` / `WM_SYSKEYDOWN`（`HwndSource` 钩子），按**物理键码（VK）**
>    匹配。输入法（TSF/IME）会在 WPF 之前改写 `Key`，`Ctrl+,` 这类标点组合在中文输入法下
>    经常收不到 `PreviewKeyDown`。
> 3. 兜底是 `PreviewKeyDown`，把 `Key.System` / `Key.ImeProcessed` / `Key.DeadCharProcessed`
>    归一化后再查同一张表，覆盖没有物理键的合成输入。
>
> **不使用** `Window.InputBindings`：`KeyGesture` 对 `,` 这类 OEM 键的匹配不可靠，
> 且不认 `Key.System`，匹配规则藏在框架里无法断言。
> 右键菜单的键位提示由同一张表填入，不存在菜单与实现不一致的可能。
>
> **为什么 `Ctrl+,` 要特殊处理**（2026-11-04 实测记录）：
> 前两版依次用 `KeyGesture`、VK 匹配都没能让真实按键生效，但注入 `WM_KEYDOWN` 能生效。
> 已排除"被其它程序注册成全局热键"（裸进程 `RegisterHotKey` 成功）。
> 剩下的变量都在输入链路下层（输入法 hook、键盘布局），进程内无法断言，
> 因此不再猜：改用系统热键通道，由系统在分发按键之前处理，输入法与 WPF 的 Key 归一化全被绕过。
> 代价是热键是系统级的，所以只在窗口激活期间持有，绝不长期占用。
>
> 排查工具：`Jianlan.exe --keydebug` 会把每条按键消息写进 `%LOCALAPPDATA%\Jianlan\logs\keydebug.log`
> （物理键码、修饰键、焦点元素、命中的命令），默认关闭，不写盘。

## 1. 标签页

| 快捷键 | 动作 |
|---|---|
| `Ctrl + T` | 新建标签页 |
| `Ctrl + W` | 关闭当前标签页 |
| `Ctrl + Shift + T` | 恢复最近关闭的标签页 |
| `Ctrl + Tab` | 下一个标签页 |
| `Ctrl + Shift + Tab` | 上一个标签页 |
| `Ctrl + 1…8` | 跳到第 N 个标签页 |
| `Ctrl + 9` | 跳到最后一个标签页 |

标签栏的鼠标操作（不占键位，不写进键位表）：

| 操作 | 效果 |
|---|---|
| 中键点击标签 | 关闭该标签页 |
| 拖动标签 | 调整顺序（位移 < 6px 视为点击，避免手抖改序） |
| 滚轮 | 标签超出宽度时横向滚动（标签多时自动把活动标签滚进视野） |
| 右键标签 | 固定/取消固定、关闭 / 关闭其他标签页 / 关闭右侧标签页 / 复制路径 / **在新窗口打开** |

「在新窗口打开」开的是**同一进程里的第二个窗口**，不是新进程：新进程会被单实例守卫
把启动参数转交给已有窗口，结果"开新窗口"变成"让已有窗口跳过去"。副窗口只带被点那个标签的路径
（和本标签的分屏另一半），不恢复会话、不记窗口位置、不注册系统热键。关掉它不影响主窗口。

在**文件列表**里开新标签（FR-2.10，同样不占键位）：

| 操作 | 效果 |
|---|---|
| 中键点击文件夹 | 在新标签页打开 |
| `Ctrl + 左键` 点击文件夹 | 同上 |
| 中键点击导航栏的系统节点 / 标签 | 在新标签页打开（FR-1.2.6，与列表里的手势一致；收藏项同样支持） |
| 把文件夹拖到标签栏上 | 用指针下的那个标签打开（FR-6.11）；落在标签之间的空白处则开新标签 |
| 双击 / `Enter` 进入文件夹 | 默认替换当前目录；打开设置项「文件夹在新标签页打开」后改为新标签 |

两条鼠标手势开出的标签默认**切过去**；设置项「新标签页在后台打开」打开后留在后台，
适合连开一批目录再回来。**代价**：`Ctrl + 点击` 被手势占用后，文件夹不能再这样多选
（文件不受影响）——多选文件夹请用 `Shift + 点击`、`Ctrl + A`，或在空白处按住拖动框选
（FR-6.7，见 §4 的"鼠标拖选"）。
`Ctrl + 拖拽` 不受影响，仍是"强制复制"：手势判定在**松开**时做，且一旦拖动过就不算点击。

拖到标签栏是**打开**，不移动任何文件：拖来的文件夹由指针下的标签导航过去（目标标签若是主页
或标签结果页，自动切回目录浏览），落在空白处则开新标签；一次拖多个时只有第一个进目标标签，
其余各开一个新标签——同一个标签连着导航只会剩下最后一个，看起来像"拖了五个只开了一个"。
拖来的**文件**交给系统默认程序打开。目标标签会套一个方框，与排序用的那条竖线分开。

## 2. 导航

| 快捷键 | 动作 |
|---|---|
| `Alt + ←` | 后退 |
| `Alt + →` | 前进 |
| `Alt + ↑` | 上一级 |
| `Backspace` | 上一级 |
| `Ctrl + L` | 聚焦地址栏并全选 |
| `Ctrl + F` | 聚焦当前目录的搜索框并全选（FR-6.13） |
| `Esc`（搜索框内） | 清空搜索；已为空时把焦点交回文件列表 |
| `Enter` / `↓`（搜索框内） | 跳到结果列表并选中第一项 |
| `Esc`（列表内，搜索态） | 退出搜索，恢复完整列表；正在计算文件夹大小时优先取消计算 |
| `Enter`（地址栏内） | 跳转到输入的路径；有候选选中时跳到选中项 |
| `↓` / `↑`（地址栏内） | 在补全候选里移动选中项，**不改地址栏文字** |
| `Tab`（地址栏内） | 用候选补全到地址栏，不跳转；目录自动补 `\` 以便继续输入下一层 |
| `Esc`（地址栏内） | 有候选时先关候选；再按一次退出编辑态 |
| `F5` | 刷新当前目录 |
| `Ctrl + R` | 刷新当前目录 |
| `Ctrl + D` | 收藏：有选中项时收藏选中的那些，没有选中则收藏当前目录（FR-7.1 / FR-7.2） |
| `Ctrl + H` | 显示/隐藏历史记录 |

鼠标（不占键位）：

| 操作 | 动作 |
|---|---|
| 鼠标后退键（侧键 1，靠掌心那颗） | 后退（FR-6.2），等同 `Alt + ←` |
| 鼠标前进键（侧键 2） | 前进，等同 `Alt + →` |

侧键读的是窗口消息 `WM_XBUTTONDOWN`，不是 WPF 的鼠标事件——后者收不到侧键，
与 `Ctrl+,` 是同一类输入链路问题（见文首）。没有侧键的鼠标不受影响；侧键在
资源管理器里改了用途的，这里仍按"后退/前进"处理，本程序不读系统的按键映射。

导航栏本身也有一条鼠标手势（FR-1.2.4）：拖动侧栏与列表之间那条竖线的任一侧 5px 可调宽度
（160–320），**双击**那条线回到默认 184。宽度拖完立即写进设置，重启保持。
「回收站 / 网络」两个节点是系统命名空间，点击交给资源管理器打开（本程序的列表按路径工作）。

「此电脑」（FR-1.2.2）点一次展开、再点收起。展开后逐盘列出**盘符 + 卷标 + 剩余空间**，
点盘符进该盘根目录（中键开新标签）；没有卷标的盘按类型显示（本地磁盘 / 可移动磁盘 /
网络驱动器…），容量读不到的盘（断线的映射盘、空仓光驱）只显示盘符。插拔 U 盘与光盘
会在 1 秒内自动更新，不用按 `F5`；展开状态记在设置里（FR-1.2.7），重启保持。

## 4. 文件操作

| 快捷键 | 动作 |
|---|---|
| `Enter` | 打开选中项 |
| `Ctrl + A` | 全选 |
| `Ctrl + C` / `Ctrl + X` / `Ctrl + V` | 复制 / 剪切 / 粘贴 |
| `Delete` | 删除到回收站 |
| `Shift + Delete` | 永久删除（需二次确认） |
| `F2` | 就地重命名（见下方「重命名手势」） |
| `Ctrl + Shift + N` | 新建文件夹 |
| `Ctrl + Shift + M` | 新建文本文档 |
| `Alt + Enter` | 打开属性对话框 |
| `Ctrl + Shift + C` | 复制完整路径 |
| `Ctrl + Z` | 撤销最近一次操作（FR-6.8） |
| 菜单键（`VK_APPS`） | 打开上下文菜单（与右键等效） |

重命名手势（三种入口，同一套行内编辑）：

| 入口 | 动作 |
|---|---|
| 再点一次文件名 | 该行已选中、且只选中这一项时，第二次单击**文件名文字**进入编辑 |
| `F2` / 右键「重命名」 | 对当前选中项进入编辑 |
| `Ctrl+Shift+N` / `Ctrl+Shift+M` | 新建后**直接**进入编辑，默认名整名选中，敲字即替换 |

编辑中：`Enter` 提交并保持选中在被改名的那一项（不跳转、不重新定位）；
其余出口一律**放弃**，磁盘一个字都不动——`Esc`、点列表空白、点别的行、点工具栏或侧栏、
切标签、换目录、把这一行滚出视野、关窗格。只有 `Enter` 会改盘：文件管理器没有确认框，
敲一半的名字被鼠标顺手点一下就落盘，改错的代价比丢几个字大得多。

方向键：刚进编辑时（整名或词干正选中、还没动过内容）四个方向键只做"去端点"——
`←` / `↑` 到最左，`→` / `↓` 到最右；动过之后（敲了字、点过编辑框内部、或者已经按过
一次方向键）恢复成逐字移动。少了后半段，名字长一点就再也插不进中间。

改扩展名要先确认：`Enter` 提交时如果扩展名变了（`报告.docx` → `报告.md`），先弹一个
确认窗，点「是」才真改，点「否」留在编辑态并保留改过的名字。大小写变化（`.TXT` → `.txt`）
不算改动；目录改名从不提示，文件夹名里的点不是扩展名。

进入编辑时只选中扩展名之前那一段（`报告.docx` 选中「报告」，`.gitignore` 整名选中），
文件夹没有扩展名概念，整名选中。名字不合法或与现有项重名时**留在编辑态**，
红框 + 全选 + 状态栏给出原因，下一次敲字直接覆盖。

三条让位规则，都是为了不跟已有手势打架：

- 带 `Ctrl` / `Shift` / `Alt` 的点击仍是加选与新标签，一律不改名；
- 点图标、色点、名称列右侧的空白只选中，与资源管理器一致；
- 设置里选「单击打开」时这个手势整体让位（否则两次点击都变成打开）；分屏里点另一个
  窗格已选中的项，第一下只切换活动窗格。

撤销（FR-6.8）：

| 最近一次操作 | 撤销做什么 |
|---|---|
| 新建文件 / 文件夹 | 送回回收站；**动过就不撤**（大小或修改时间对不上就跳过） |
| 重命名 | 改回原名；原名已被占用时跳过，绝不覆盖 |
| 粘贴（复制） | 删掉副本，源文件不动 |
| 剪切 / 移动 | 搬回原处 |
| 删除到回收站 | 从回收站还原 |

只保留**一步**：撤完再按 `Ctrl+Z` 什么也不会发生，不会连着把更早的事一件件退回去。
永久删除（`Shift+Delete`）之后栈会清空——上一次操作的记录还挂着，按下去就会撤掉更早的
那件事，那才是真正的意外；此时状态栏明说"此操作不可撤销"。
撤销本身只用可回退的动作：搬回去、改回原名、送回收站、从回收站还原。判定错了，文件仍在
回收站或原处，用户自己捞得回来。

鼠标拖选（FR-6.7）：

| 操作 | 效果 |
|---|---|
| 在列表**空白处**按下并拖动 | 框选：拖动中实时显示选框与选中结果，松开即定稿 |
| `Ctrl` + 空白处拖动 | 框选并**追加**到按下时已有的选中项；不按 `Ctrl` 则替换 |
| 从某个文件/文件夹上按下并拖动 | 拖放，不是框选 |

同一个左键手势有两个意思，按**按下的位置**分流：落在条目上是拖放，落在空白处是框选。
这样"重新框一次"不会先把上一批拖走。拖动滚动条也不算框选——那是在滚列表。
框住的范围只要与条目**有交叠**就算选中，不要求整行完整落在框里。
只对**当前看得见**的行有效：滚动到屏幕外的行没有界面容器，与资源管理器一致。

| 操作 | 动作 |
|---|---|
| 工具栏右端的分栏按钮 | 同 `F3`。按钮有选中底色时表示分屏开着；只有主窗格有这颗按钮 |

每个标签各自带一对窗格（ADR-0009）。

> 在设计稿里出现过，**均未实现**：前者被 `F3` 取代（`Ctrl+\` 在多数中文输入法下会被占用），
> 后者属 P2。

## 6. 标签色（M2）

| 快捷键 | 动作 |
|---|---|
| `Alt + 1…8` | 给选中项打上第 N 号颜色标签 |
| `Alt + 0` | 清除选中项的标签 |

**同一个文件可以同时有多种颜色。** 右键菜单里的颜色项是可勾选的：点一次加上、再点一次去掉，
勾上第二种颜色不会把第一种顶掉（`Alt + 数字` 走的是同一套切换逻辑）。行名称前最多显示
**三个**色点，按颜色位序取前三个——行高 28px 塞不下更多。超过三种时，记录与菜单勾选状态
仍然是完整的（导航栏「标签」区的计数也算上第 4 色），只是行上看不到它。

八种颜色的名字可以在设置里改（把「红」改成「紧急」），改完侧栏、右键菜单、状态栏一起变。
只保存被改过的几项，清空输入框即恢复默认名。
## 7. 预览窗格（M2）

| 快捷键 | 动作 |
|---|---|
| `Alt + P` | 开/关预览窗格（FR-9.1.1）。与资源管理器同一手势 |
| `Ctrl + Shift + P` | 同 `Alt + P`。远程桌面/某些输入法会把 `Alt` 组合截走，留一条备用路 |

鼠标：

| 操作 | 动作 |
|---|---|
| 拖动预览左侧的分隔条 | 改宽度（240–720），拖完即落盘 |
| 双击分隔条 | 复位 320 |
| 预览里的「立即预览」 | 网络位置与可移动设备上的文件不自动预览（FR-9.2.8），点它触发一次 |

预览标题行右侧的 `×` 关闭整个预览窗格，并同步设置页「显示预览窗格」的勾选值。
选中单个文件时，下方出现「打开 / 复制路径 / 删除」三颗按钮（FR-9.1.5）——
它们作用的对象是**预览当前显示的那个文件**，不是列表选中集：预览有防抖，
两者可能瞬间不一致，以显示为准。多选时这三颗按钮隐藏。

预览是**窗口级**的一栏：分屏时两个窗格共用一个，永远反映焦点窗格的选中项。
切到主页或标签结果页时这一栏自动收起（那两种形态没有"选中的文件"），切回目录标签自动恢复——
收的是显示，不是你按 Alt+P 的意图。

| `Alt + F4` | 退出 |
| `Ctrl + Shift + W` | 关闭窗口（含全部标签页） |

## 9. 键盘焦点与 Tab 顺序（FR-10.7）

Tab 的实测顺序（单窗格、打开预览、选中一个文本文件）：

```
标签栏 → 导航栏 → 设置 → 工具栏（导航按钮 → 面包屑 → 搜索 → 视图切换）
      → 列头 → 文件列表 → 预览分隔条 → 预览文本 → 回到标签栏
```

双窗格时先走完第一格的全部停靠点，再走第二格。
预览窗格只有"能用键盘做什么"时才占停靠点：文本预览（方向键滚动、`Ctrl+C` 复制）
与说明态的「立即预览」按钮各是一个，纯图片/处理器预览不占。

- **列表整块只停一次**：文件列表与导航栏各自只占一个 Tab 停靠点，项间移动用方向键。
  否则万项目录里要按一万下 Tab 才出得去。
- **标签栏**：Tab 逐个走过标签；`Enter` / `Space` 切换，`←` `→` 直接切到相邻标签。
  标签上的关闭按钮不在 Tab 序列里（12 个标签会有 12 颗），键盘关闭用 `Ctrl+W`
  或右键菜单里的「关闭」。
  > 这四个键在标签上**归标签自己处理**：窗口的 `PreviewKeyDown` 会先看到它们，
  > 若不主动让路，`Enter` 会被全局键位表的「打开选中项」截走——焦点在标签上按 Enter
  > 结果打开了旁边列表里的文件（AC-08 走查发现，见 `docs/ac08-accessibility.md` §5）。
  > 让路范围只有这四个键，`Ctrl+W` / `F5` / `Ctrl+Tab` 等全局键位在标签上照常生效。
- **地址栏**：默认是面包屑，每一段都是一个停靠点；`Ctrl+L` 切到可编辑输入框。
- 计划里写的"地址栏 → 列表 → 导航栏 → 标签栏"没有照做，原因见
  `docs/m2-plan.md` §4.10 第 4 条：跨可视树分支重排违反"与视觉顺序一致"。
