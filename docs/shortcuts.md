# 快捷键

> 对应 FR-10.6。键位一经发布不再变更；新增键位必须避开下表已占用组合。
>
> **实现状态（M1）**：`Alt+←/→/↑`、`Backspace`、`Ctrl+L`、`F5`、`Ctrl+R`、`Ctrl+Shift+1/2`、
> `Ctrl+Shift+D`、`Ctrl+,`、`Enter`、`F2`、`Delete`、`Shift+Delete`、`Ctrl+C/X/V`、`Ctrl+A`、
> `Ctrl+Shift+N`、`Ctrl+Shift+M`、`Ctrl+Shift+C`、`Alt+Enter`、菜单键（`VK_APPS`）已可用。
> `Ctrl+Shift+3`（大图标）**不绑定**：该视图决定不做，见 `docs/adr/0005-large-icon-view.md`。
>
> **实现状态（M2 / S3）**：标签页 10 条（`Ctrl+T`、`Ctrl+W`、`Ctrl+Shift+T`、`Ctrl+Tab`、
> `Ctrl+Shift+Tab`、`Ctrl+1…8`、`Ctrl+9`）已可用，全部走**窗口表**（标签集合属于窗口，
> 不属于某个窗格，见 `docs/pane-refactor.md` §7）。
>
> **实现方式**：键位表在 `Lingpane.App/Input/KeyBindings.cs`，采用**三入口**：
>
> 1. `Ctrl + ,` 单独走**系统热键**：窗口激活时 `RegisterHotKey`，失活立即注销，
>    命中时收到 `WM_HOTKEY` 打开设置。验证过程见下方"为什么 Ctrl+, 要特殊处理"。
> 2. 主入口是窗口消息 `WM_KEYDOWN` / `WM_SYSKEYDOWN`（`HwndSource` 钩子），按**物理键码（VK）**
>    匹配。输入法（TSF/IME）会在 WPF 之前改写 `Key`，`Ctrl+,` 这类标点组合在中文输入法下
>    经常收不到 `PreviewKeyDown`。
> 3. 兜底是 `PreviewKeyDown`，把 `Key.System` / `Key.ImeProcessed` / `Key.DeadCharProcessed`
>    归一化后再查同一张表，覆盖没有物理键的合成输入。
>
> **不使用** `Window.InputBindings`：`KeyGesture` 对 `,` 这类 OEM 键的匹配不可靠，
> 且不认 `Key.System`，匹配规则藏在框架里无法断言。
> 右键菜单的键位提示由同一张表填入，不存在菜单与实现不一致的可能。
>
> **为什么 `Ctrl+,` 要特殊处理**（2026-11-04 实测记录）：
> 前两版依次用 `KeyGesture`、VK 匹配都没能让真实按键生效，但注入 `WM_KEYDOWN` 能生效。
> 已排除"被其它程序注册成全局热键"（裸进程 `RegisterHotKey` 成功）。
> 剩下的变量都在输入链路下层（输入法 hook、键盘布局），进程内无法断言，
> 因此不再猜：改用系统热键通道，由系统在分发按键之前处理，输入法与 WPF 的 Key 归一化全被绕过。
> 代价是热键是系统级的，所以只在窗口激活期间持有，绝不长期占用。
>
> 排查工具：`Lingpane.exe --keydebug` 会把每条按键消息写进 `%LOCALAPPDATA%\Lingpane\logs\keydebug.log`
> （物理键码、修饰键、焦点元素、命中的命令），默认关闭，不写盘。

## 1. 标签页

| 快捷键 | 动作 |
|---|---|
| `Ctrl + T` | 新建标签页 |
| `Ctrl + W` | 关闭当前标签页 |
| `Ctrl + Shift + T` | 恢复最近关闭的标签页 |
| `Ctrl + Tab` | 下一个标签页 |
| `Ctrl + Shift + Tab` | 上一个标签页 |
| `Ctrl + 1…8` | 跳到第 N 个标签页 |
| `Ctrl + 9` | 跳到最后一个标签页 |

标签栏的鼠标操作（不占键位，不写进键位表）：

| 操作 | 效果 |
|---|---|
| 中键点击标签 | 关闭该标签页 |
| 拖动标签 | 调整顺序（位移 < 6px 视为点击，避免手抖改序） |
| 滚轮 | 标签超出宽度时横向滚动（标签多时自动把活动标签滚进视野） |
| 右键标签 | 固定/取消固定、关闭 / 关闭其他标签页 / 关闭右侧标签页 / 复制路径 |

在**文件列表**里开新标签（FR-2.10，同样不占键位）：

| 操作 | 效果 |
|---|---|
| 中键点击文件夹 | 在新标签页打开 |
| `Ctrl + 左键` 点击文件夹 | 同上 |
| 中键点击导航栏的系统节点 / 标签 | 在新标签页打开（FR-1.2.6，与列表里的手势一致；收藏项同样支持） |
| 双击 / `Enter` 进入文件夹 | 默认替换当前目录；打开设置项「文件夹在新标签页打开」后改为新标签 |

两条鼠标手势开出的标签默认**切过去**；设置项「新标签页在后台打开」打开后留在后台，
适合连开一批目录再回来。**代价**：`Ctrl + 点击` 被手势占用后，文件夹不能再这样多选
（文件不受影响）——多选文件夹请用 `Shift + 点击`、`Ctrl + A` 或框选。
`Ctrl + 拖拽` 不受影响，仍是"强制复制"：手势判定在**松开**时做，且一旦拖动过就不算点击。

## 2. 导航

| 快捷键 | 动作 |
|---|---|
| `Alt + ←` | 后退 |
| `Alt + →` | 前进 |
| `Alt + ↑` | 上一级 |
| `Backspace` | 上一级 |
| `Ctrl + L` | 聚焦地址栏并全选 |
| `Ctrl + F` | 聚焦当前目录的搜索框并全选（FR-6.13） |
| `Esc`（搜索框内） | 清空搜索；已为空时把焦点交回文件列表 |
| `Enter` / `↓`（搜索框内） | 跳到结果列表并选中第一项 |
| `Esc`（列表内，搜索态） | 退出搜索，恢复完整列表；正在计算文件夹大小时优先取消计算 |
| `Enter`（地址栏内） | 跳转到输入的路径；有候选选中时跳到选中项 |
| `↓` / `↑`（地址栏内） | 在补全候选里移动选中项，**不改地址栏文字** |
| `Tab`（地址栏内） | 用候选补全到地址栏，不跳转；目录自动补 `\` 以便继续输入下一层 |
| `Esc`（地址栏内） | 有候选时先关候选；再按一次退出编辑态 |
| `F5` | 刷新当前目录 |
| `Ctrl + R` | 刷新当前目录 |
| `Ctrl + D` | 收藏：有选中项时收藏选中的那些，没有选中则收藏当前目录（FR-7.1 / FR-7.2） |
| `Ctrl + H` | 显示/隐藏历史记录 |

导航栏本身也有一条鼠标手势（FR-1.2.4）：拖动侧栏与列表之间那条竖线的任一侧 5px 可调宽度
（160–320），**双击**那条线回到默认 184。宽度拖完立即写进设置，重启保持。
「回收站 / 网络」两个节点是系统命名空间，点击交给资源管理器打开（本程序的列表按路径工作）。

## 5. 双窗格（M2）

| 快捷键 | 动作 |
|---|---|
| `F3` | 开/关第二窗格（FR-3.3）。关闭后焦点回主窗格 |
| `Ctrl + Shift + E` | 同 `F3`。给键盘党的第二条路，`F3` 被别的程序占住时可用 |
| `Tab` | 切换焦点窗格（列表有焦点时。方向键在列表内换选中项，Tab 让给"换窗格"） |
| `F6` | 切换焦点窗格（与 `Tab` 等价，兼容资源管理器/Total Commander 习惯） |

鼠标：

| 操作 | 动作 |
|---|---|
| 工具栏右端的分栏按钮 | 同 `F3`。按钮有选中底色时表示分屏开着；只有主窗格有这颗按钮 |
| 拖动分隔条 | 改比例（0.15–0.85），拖完即落盘 |
| 双击分隔条 | 复位 50:50 |
| 右键分隔条 | 左右分屏 / 上下分屏 / 恢复 50:50 |

分屏形态（`splitEnabled` / `splitRatio` / `splitVertical`）是**窗口级**的：切标签不会把分屏切没了，
每个标签各自带一对窗格（ADR-0009）。

> `Ctrl + \`（开关右窗格）与 `Ctrl + Shift + →`（把当前路径设为另一窗格的目标，FR-3.9，P2）
> 在设计稿里出现过，**均未实现**：前者被 `F3` 取代（`Ctrl+\` 在多数中文输入法下会被占用），
> 后者属 P2。

## 7. 预览窗格（M2）

| 快捷键 | 动作 |
|---|---|
| `Alt + P` | 开/关预览窗格（FR-9.1.1）。与资源管理器同一手势 |
| `Ctrl + Shift + P` | 同 `Alt + P`。远程桌面/某些输入法会把 `Alt` 组合截走，留一条备用路 |

鼠标：

| 操作 | 动作 |
|---|---|
| 拖动预览左侧的分隔条 | 改宽度（240–720），拖完即落盘 |
| 双击分隔条 | 复位 320 |
| 预览里的「立即预览」 | 网络位置与可移动设备上的文件不自动预览（FR-9.2.8），点它触发一次 |

预览是**窗口级**的一栏：分屏时两个窗格共用一个，永远反映焦点窗格的选中项。
切到主页或标签结果页时这一栏自动收起（那两种形态没有"选中的文件"），切回目录标签自动恢复——
收的是显示，不是你按 Alt+P 的意图。

## 9. 键盘焦点与 Tab 顺序（FR-10.7）

Tab 的实测顺序（单窗格、打开预览、选中一个文本文件）：

```
标签栏 → 导航栏 → 设置 → 工具栏（导航按钮 → 面包屑 → 搜索 → 视图切换）
      → 列头 → 文件列表 → 预览分隔条 → 预览文本 → 回到标签栏
```

双窗格时先走完第一格的全部停靠点，再走第二格。
预览窗格只有"能用键盘做什么"时才占停靠点：文本预览（方向键滚动、`Ctrl+C` 复制）
与说明态的「立即预览」按钮各是一个，纯图片/处理器预览不占。

- **列表整块只停一次**：文件列表与导航栏各自只占一个 Tab 停靠点，项间移动用方向键。
  否则万项目录里要按一万下 Tab 才出得去。
- **标签栏**：Tab 逐个走过标签；`Enter` / `Space` 切换，`←` `→` 直接切到相邻标签。
  标签上的关闭按钮不在 Tab 序列里（12 个标签会有 12 颗），键盘关闭用 `Ctrl+W`
  或右键菜单里的「关闭」。
- **地址栏**：默认是面包屑，每一段都是一个停靠点；`Ctrl+L` 切到可编辑输入框。
- 计划里写的"地址栏 → 列表 → 导航栏 → 标签栏"没有照做，原因见
  `docs/m2-plan.md` §4.10 第 4 条：跨可视树分支重排违反"与视觉顺序一致"。

## 10. 冲突规避

以下组合**已占用，不得分配给新功能**：

`Ctrl+T` `Ctrl+W` `Ctrl+Shift+T` `Ctrl+Tab` `Ctrl+1…9` `Alt+←→↑` `Backspace` `Ctrl+L`
`F5` `Ctrl+R` `Ctrl+D` `Ctrl+H` `Ctrl+Shift+1…3` `Ctrl+Shift+D` `Ctrl+,` `Ctrl+滚轮` `F11` `Ctrl+B` `Enter`
`Ctrl+A/C/X/V` `Delete` `Shift+Delete` `F2` `Ctrl+Shift+N` `Ctrl+Shift+M` `Alt+Enter` `Ctrl+Shift+C`
`Tab` `F3` `F6` `Ctrl+Shift+E` `Alt+1…8,0` `Alt+P` `Ctrl+Shift+P` `Ctrl+,` `F1` `Alt+F4` `Ctrl+Shift+W`

实现要求：

- 键位集中定义在 `Lingpane.App/Input/KeyBindings.cs`，禁止在 XAML 的 `InputBindings` 里散写
- 快捷键表与 `docs/shortcuts.md` 必须同源，改一处即改两处
- 所有快捷键动作必须同时存在于右键菜单或工具栏，不做"只有快捷键才知道"的功能
- **新键位必须进 `KeyBindings`**：设计上的主入口是 `WM_KEYDOWN` 钩子（避开输入法改写 Key），
  但实测真实按键与投递的 `WM_KEYDOWN` 都到不了钩子，只有 `OnPreviewKeyDown` 那条兜底路径
  收得到（`Ctrl+,` 走系统热键 `WM_HOTKEY`，是唯一的例外）。只写在钩子里的键位等于没接——
  `Tab` 换窗格就踩过这个坑，详见 `docs/pane-refactor.md` §9.4
