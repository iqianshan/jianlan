# 应用图标（exe / 窗口 / 任务栏）

0.2.1 里这件事返工了三次，每次都以为改对了、每次都被任务栏打回。结论压成**四条约束**，
改图标前逐条对一遍，改完按 §5 的三步验收。**窗口标题栏和 Alt+Tab 都不是判据**——它们由 WPF
自己绘制，比任务栏宽容得多，历史上三次"看起来好了"都是在这里误判的。

## 1. 画布必须是方的，图形要铺满

Windows 把整幅画布缩放进任务栏槽位，不看图形占多少。

- 图形占画布 **98%**，长宽比 **1:1**。系统自带图标普遍占 88%~100%（125% DPI 实测：
  微信 / Edge 30×30，资源管理器 30×27）。
- 品牌的板体是 **1.17:1**（文件夹造型），按宽度铺满时高度只能到 85%，永远够不到方形图标的
  100%——这不是留白没调够，是比例问题。第一次把留白从 75%×64% 放到 94%×80%，实测 29×24，
  一眼仍矮一截；改成方形铺 98% 之后才是 29×29。
- 拉伸只作用于**应用图标**。品牌素材包里的图形标、组合标保持 1.17:1 原比例，对外投放不受影响。
  应用图标用方形板是通行做法，跟 logo 本身的比例是两件事。
- 字形用**不透明纯白**，不要镂空。镂空在浅色背景下像白字，到深色任务栏上透出的是任务栏底色，
  蓝板与字同色系，对比只剩一点点。

## 2. ≤128 的帧写未压缩位图，只有 256 档用 PNG

传统图标路径（`LoadImage`、标题栏、任务栏）对 PNG 压缩帧不稳。

- 每帧：`BITMAPINFOHEADER`（40 字节，高度写两倍）+ BGRA **自下而上** + AND 掩码（1bpp，行按 4 字节对齐）。
- 档位：16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256。
- 代价是体积从 7.8 KB 涨到 119 KB，可以接受；换来的是任何一条老路径都认。
- 曾经吃过一次"改了没落到文件里"：早先有一版 ico 号称混用 DIB，实际 128 档只有 1389 字节，
  仍是纯 PNG 帧。改完要回读文件确认，不能只看脚本输出。

## 3. 图标只有一个来源：代码

**XAML 上不要写 `Icon="pack://…"`。** 写了 WPF 会自己按 32/16 逻辑像素生成一份 HICON，
和代码里按 DPI 从 exe 资源取的那份互相覆盖——这正是历史注释里"设了 `Window.Icon`、
`WM_GETICON` 也查得到，任务栏却仍画默认图"的直接原因。

现在只有一处：`MainWindow.ApplyIconFromExeResources()`。

```
LoadImage(GetModuleHandle(null), "#32512", IMAGE_ICON, size, size, LR_SHARED)
```

- 尺寸按 DPI 算（125% 下取 40 / 20；150% 下 48 / 24）。
- **`LR_SHARED` 必带**：句柄交系统托管，不会因为窗口销毁或某处误 `DestroyIcon` 变成空。
- 两条消息 + 两个类字段，四者都设：`WM_SETICON(BIG/SMALL)` 与
  `SetClassLongPtr(GCLP_HICON = -14)` / `SetClassLongPtr(GCLP_HICONSM = -34)`。
- **`OnSourceInitialized` 和 `Loaded` 各调一次**：首次 `Show()` 若触发 `HwndSource` 重建，
  早先挂的 `WM_SETICON` 会留在旧对象上。

## 4. 外壳取图标是三级回退，中间一级默认是空的

外壳按「窗口 `WM_GETICON` → 窗口类图标 → 系统默认图」逐级回退，**任一级在某个时机返回 0
就直接掉到默认图**。

WPF 窗口的**窗口类图标恒为空**（`GCLP_HICON` / `GCLP_HICONSM` 都是 0），记事本这类原生程序
`WNDCLASS` 里自带 `hIcon`，所以从不出现这个问题——这也是它看起来像"偶发"的原因。
§3 里 `SetClassLongPtr` 那两句就是为了补掉这个空档，不是可选项。

## 5. 验收

改完必须走完这三步，缺一步都可能误判：

1. **看日志**：`%LOCALAPPDATA%\Jianlan\logs\`（便携版是解压目录下的 `data\logs\`）
   当天的文件里搜 `icon.apply`，应为

   ```
   icon.apply hwnd=… big=40/True small=20/True cls=True/True dpi=1.25
   ```

   资源那两处是 `False` → 产物问题（ico 没打进去）；`cls` 是 `False` → 回退链断档（§3 没生效）。
2. **截任务栏，不看窗口**：图标要与相邻应用同高（125% 下 30×30 的槽位里取到 29×29）。
   主屏、副屏各看一次。
3. **重新解压到干净目录再冷启动一次**。图标缓存会替上一版"兜住"，在旧目录里看不出问题；
   解压新目录仍正常，才算真的对。

## 6. 不要做的事

- **不要再把便携版图标问题归给"没有开始菜单快捷方式 / 没有 AUMID"。** 这条早期结论是错的：
  同一个没有快捷方式的便携版 exe，补上窗口类图标之后直接双击就正常。应用身份影响的是
  固定到任务栏、通知归属这类功能，不是任务栏按钮画哪张图。
- 不要为深色任务栏单独做一套图标。任务栏图标不随主题切换，Windows 只认 exe 与窗口各一份；
  分主题等于维护只在切换瞬间生效的第二套方案，收益不抵成本。
- 不要只改 `Assets/Brand/jianlan.ico` 就以为完事。exe 上的图标是 `<ApplicationIcon>` 在编译时
  嵌进去的，不重新 `dotnet publish`，publish 与 dist 里还是旧图。
- 不要把「窗口标题栏显示对了」当成通过。

## 7. 三次返工各自错在哪

| 轮次 | 改了什么 | 为什么还不够 |
| --- | --- | --- |
| 1 | ico 全部改用 DIB 帧 + 从 exe 资源取图 | 画布比例没动，任务栏仍矮一截；窗口内图标已正常，掩盖了问题 |
| 2 | 板体从 75%×64% 放到 94%×80%，字形改实心白 | 没意识到 1.17:1 的长宽比决定了高度上限 85% |
| 3 | 方形板体铺 98%；去掉 XAML `Icon`、加 `LR_SHARED`、补 `GCLP_HICON(SM)` | 通过 |

第三轮之前一直把它们当三件事分头修（尺寸、配色、身份），实际是**一条链上的三个断点**：
几何决定画多大、帧格式决定认不认、回退链决定取不取得到。任何一段断了，表现都是同一张白卡片。
