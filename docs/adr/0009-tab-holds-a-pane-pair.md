# ADR-0009：标签 = 一对窗格

- 状态：**已接受**（2026-11-05）
- 影响：FR-3.2 的解释、`TabViewModel`/`TabHostViewModel`、`session.tabSecondPaths`、
  `docs/pane-refactor.md` §6/§9
- 关联：FR-2 多标签、FR-3 双窗格、ADR-0008（双窗格 90 MB 档）

## 背景

FR-3.2 原文写的是「每窗格独立标签组与导航栈」。字面实现意味着分屏之后**两套标签栏**：
左右各一条，各有自己的标签集合、各自的 `Ctrl+1…9`、各自的关闭按钮。

S3 已经按"窗口顶部只有一条标签栏、标签各自持有一份 `PaneViewModel`"做完（§6）。
到 S4 要开第二个窗格时，这个前提必须立刻定下来——它决定 `TabHostViewModel` 里的元素
是"一个浏览区"还是"一对浏览区"，改晚了所有命令目标、会话结构、标签操作都要重写一遍。

## 决定

**一个标签内含 1–2 个窗格**（`TabViewModel.Primary` 必有、`Secondary` 分屏时才有），
顶部仍然只有一条标签栏。

三条理由：

### 1. 只有一条标签栏时，`Ctrl+1…9` 才有明确归属

两套标签栏意味着同一个 `Ctrl+3` 有两个候选（左第 3 个、右第 3 个）。要么加一层
"先按 `Tab` 选标签栏、再按数字"的间接操作，要么按焦点决定——前者多一次按键，
后者让相同的键在不同时刻做不同的事。用户记不住。

一条标签栏就没有这个问题：`Ctrl+3` 永远是"第 3 个标签"，而当前焦点在哪个窗格
不影响这件事。

### 2. 窗口窄下来时，两条标签栏都会挤成省略号

S3 实测：1000px 宽的窗口里，单条标签栏只露 5–6 个标签，再窄就要横向滚动（§8 欠账）。
分屏后每个窗格只剩一半宽度，两条标签栏各自在一个 500px 的框里排 12 个标签——
每个标签都是「临…」。标签的意义是"我能一眼看到我开了哪些目录"，退化成省略号就没有意义了。

### 3. 分屏是**窗口形态**，不是某个标签的属性

`_splitEnabled` 与 `Layout.SplitEnabled` 都挂在窗口上。开着分屏切标签，新标签也照样是分屏——
否则"切个标签分屏就没了"会被当成 bug 报上来（Total Commander / Q-Dir / 资源管理器都是这个行为）。

既然分屏是窗口级状态，把一个标签固定绑成"一个窗格"就自相矛盾了：分屏一开，
每个标签都得凭空长出一个窗格。反过来把标签定义成"一对窗格"，窗口级分屏开关只决定
**第二窗格显不显示**，模型和界面就对上了：

| 操作 | 结果 |
|---|---|
| 开分屏（`F3`） | 当前标签立刻长出第二窗格；其余标签等被激活时再长（懒创建） |
| 关分屏（`F3`） | 所有标签的第二窗格**只丢掉视图、保留路径**（`DropSecondary`） |
| 切标签 | 整对窗格换绑；窗口分屏状态不变 |
| 会话恢复 | `session.tabs[i]` + `session.tabSecondPaths[i]`，平行数组 |

「关分屏只丢窗格不丢路径」是配套决定：12 个标签各留一个空壳窗格等于把
ADR-0008 的 90 MB 预算花在看不见的地方；而把路径一起丢掉，用户下次开分屏
又要重新导航一次。

## 备选方案与不选的理由

**A. 严格按原文做两套标签栏。** 三条理由逐一反对（见上）。另外还多出一个实现代价：
`TabStrip` 要变成每窗格一份、拖拽排序要在两套之间搬家、右键菜单的"关闭其他标签页"
要区分左右。为一个 P0 需求里都没写到的形态付出这些，不划算。

**B. 分屏后第二窗格没有标签概念，只是一块"临时预览区"。** 否决：那就等于第二窗格
不能有自己的历史栈（后退/前进要能独立工作，FR-3.2 的"导航栈"部分）。
用户从右窗格后退一步再切标签，回来还得能前进——这要求右窗格有持久身份。

**C. 改成真·两条标签栏 + 一条共享的地址栏。** 更糟：地址栏归谁？焦点在哪边就归哪边，
于是"我看到地址栏显示 A、列表显示 B"这类错位会常态化。

## 后果

- `TabViewModel` 成为"一对窗格"的容器：`Primary` / `Secondary` / `ActivePane` / `IsSplit`；
  `DisplayName` 跟随**活动窗格**（焦点放到右边并导航时，标签名必须跟着变）
- `TabHostViewModel.Tabs` 的元素类型从 `PaneViewModel` 换成 `TabViewModel`；
  `SnapshotPaths()` 与 `SnapshotSecondPaths()` 必须成对取，否则两个列表会错位
- 会话多一个平行数组 `session.tabSecondPaths`（与 `tabs` 等长，空串 = 该标签没开分屏）。
  不用对象数组是为了不写迁移：旧版本读到未知字段按 `JsonExtensionData` 原样保留
- FR-3.2 的验收口径改为「两窗格路径、历史互不影响」，`docs/requirements.md` 同步
- `Ctrl+1…9`、中键关闭、拖动排序、右键菜单全部只作用于"标签"，不需要区分左右

## 复查条件

1. 用户反馈"想在左窗格固定 A 目录、右窗格独立开自己的标签组"——说明两组标签是真实需求，
   届时按方案 A 重做，且必须先解决 `Ctrl+数字` 的归属
2. 第二窗格的懒创建导致"切标签后右窗格闪一下空白"被报为体验问题——
   说明该提前建好（代价是 12 份空壳窗格的内存，需要重估 ADR-0008 的 90 MB）
3. `tabSecondPaths` 与 `tabs` 出现长度不一致的线上数据——说明归一化没盖住，
   补齐/截断逻辑要重新过一遍
