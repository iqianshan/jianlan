# ADR-0005：M1/M2 不实现大图标视图

- 状态：已接受
- 日期：2026-11-04
- 相关：ADR-0002（内存预算）、ADR-0003（列表整体替换）、`docs/performance-gate.md`

## 背景

需求 FR-5.x 列了三种视图：详细信息、列表、大图标（磁贴）。前两种已实现，都跑在
`VirtualizingStackPanel` 上，万项目录只创建可视区内的容器。

大图标是二维布局，`VirtualizingStackPanel` 只能一维虚拟化，必须换成
`VirtualizingWrapPanel` 这类基于 `IScrollInfo` 的自定义面板：WPF 没有内置。

## 分析

### 不做的直接代价

不做虚拟化直接上 `WrapPanel` 意味着：万项目录要创建一万个 `ListBoxItem` + 一万个
图标 `Image`。按已测数据，详细信息视图万项常驻内存约 114MB（NF-05 限 150MB）；
容器本身的视觉树开销远大于数据对象，仅容器一项就会把私有提交推到数倍于预算，
首屏时间也会从 243ms 量级掉到秒级。**这与唯一硬目标（启动快、稳定）直接冲突。**

### 做的真实成本

要做得住，需要自研虚拟化面板：

| 工作项 | 说明 | 风险 |
|---|---|---|
| `IScrollInfo` 面板 | 按行列计算可视区、回收容器、处理 `MeasureOverride`/`ArrangeOverride` | 高。计算错误表现为滚动错位、空白区、无限测量循环 |
| 选中/键盘导航 | 方向键跨行、Shift 范围选、与虚拟化回收共存 | 中 |
| 图标尺寸与 `Ctrl+滚轮` | 列数随尺寸变化，需重算布局 | 中 |
| 缩略图 | 大图标的实际价值主要来自缩略图；`ImageSource` 解码无上限会撑爆内存（ADR-0002 第三条约束） | 高 |
| 回归验证 | 虚拟化面板的 bug 只在特定尺寸/DPI/缩放下出现，验证成本高 | 高 |

粗估 3–5 个工作日只够做出"能滚动、不错位"的骨架，缩略图另计。

### 收益

面向普通用户浏览照片、视频、下载目录时的"看图"体验。对以键盘操作为主的
文件管理场景，详细信息视图的信息量更大。

## 不实现带来的问题（明确记录，不藏）

1. **没有缩略图**：照片、视频、设计稿目录只能看文件名，找图必须逐个打开。
2. **没有图标尺寸调节**：`Ctrl+滚轮` 在主界面无效。
3. **`Ctrl+Shift+3` 是空键位**：文档里占着，但按下没有反应（已在 `shortcuts.md` 标注）。
4. **设置里的"默认视图"没有第三项**：`settings.json` 的 `defaultView` 仍保留 `grid` 值，
   读到 `grid` 时回落列表并在状态栏提示，不报错。
5. **与资源管理器的心智差**：新用户第一次打开会先找图标视图，找不到会认为"功能不全"。
6. **磁贴/彩标方向被推迟**：M2 的彩标在图标视图上更好用，短期只能在详细信息视图里用色点。

## 决策

M1、M2 不实现大图标视图。

- `settings.json` schema 保留 `defaultView: grid`，读到即回落列表并提示，不做迁移；
- `Ctrl+Shift+3` 保留占用不绑定，避免将来冲突；
- 界面不放"大图标"按钮，只保留"详细/列表"两枚，避免按钮点了没反应；
- M3 视用户反馈重新评估：只有当虚拟化面板能与现有预算（NF-05 / NF-05R）和启动预算
  同时达标时才做，否则维持不做的结论。

## 替代方案（已采纳的临时方案）

- 右键菜单"复制完整路径"，配合系统资源管理器看图；
- 首次进入目录按类型/大小排序，缩小人工筛选范围；
- M2 加入预览窗格（`F11`）后，选中单个图片即可预览，覆盖"只想看一眼"的多数场景。

## 后果

正面：M1/M2 不背虚拟化面板的风险，性能门禁不受新增面板影响。
负面：如"不实现带来的问题"所列 6 条，需要在对外说明中如实告知，不能宣传"支持大图标"。
