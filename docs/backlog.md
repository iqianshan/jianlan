# 后续需求（未排期）

按"想清楚了但暂不做"收录。每条记清楚做什么、为什么暂缓、开工前必须先解决什么，避免下次重新评估一遍。

## 1. 复制/移动进度窗与取消

**需求**：跨目录复制大文件时弹窗显示总进度、当前文件、已传/总量，并提供取消。

**现状**：`FileOperations.CopyAsync` 走 `Task.Run(CopyCore)`，逐项 `File.Copy`，无 `IProgress`、无 `CancellationToken`；界面只有状态栏一句「正在复制…」。应用内拖放（`PaneView.DragDrop.cs`）与粘贴共用这一条路径。

**方案要点**（2026-11-23 评估结论）：

- 底层用 `CopyFileEx` 而不是 `FileStream`。`File.Copy` 内部就是它，换掉不改变任何语义（ADS、时间戳、属性、稀疏、SMB 服务端复制）；流式复制会丢 ADS、丢压缩/加密属性，并让网络盘变慢数倍。取消靠 `pbCancel` → `ERROR_REQUEST_ABORTED(1235)`。
- 取消时**目标半截文件必须删掉**，已完成项保留；这一点要写进窗口文案，否则用户会以为全回滚。
- 进度窗必须**常驻复用**（照 `ConfirmWindow` 的 `_instance ??= new` + `ModalSession`）。每次 `new` + `ShowDialog()` 会重演 AC-03 的 `dui70.dll` 崩溃。
- 弹出阈值：总量 ≥200 MB 或预估 ≥2 秒，且延迟 500 ms 弹出；低于阈值走状态栏。
- 同一时刻只允许一个传输；第二次粘贴先直接拒绝并提示，不做队列。
- 取消后**不清空既有撤销栈**，只是本次不记录（现在 `PasteAsync` 在 `Ok == false` 时 `Undo.Clear()`，会把用户之前的撤销记录一起清掉）。

**工作量**：最小可用（大文件 + 模态窗 + 取消）约 3~4 个工作日；非模态浮层、传输队列、速度/剩余时间属二期。

**暂缓原因**：0.2.1 收尾阶段，优先级低于稳定性与发版；改动触及核心复制层，需要一段完整的回归窗口。

**备选（1.5 天）**：不做弹窗，把「计算文件夹大小」那套状态栏进度 + 取消按钮扩展到复制，零模态风险。

## 2. 地址栏输入文件路径能否直接打开

**需求**：在地址栏输入一个文件的完整路径（如 `C:\Users\me\setup.exe`）回车，按系统默认程序打开它。资源管理器是这么做的，本程序现在的回答是「路径不存在」。

**现状**：`PaneView.OnAddressKeyDown` 只有一条判据——`Directory.Exists(target)`，为假就 `SetHint(Hint_PathNotFound)` 然后什么都不做。它连"这是个存在的文件"都判断不出来，所以不是"打开了但没提示"，而是**根本打不开**。因此这一条**不是 FR-5.2.11 的漏洞**，是能力缺口。

**方案要点**（2026-11-27 评估）：

- 判据改成三段：`Directory.Exists` → 导航；`File.Exists` → 打开；都不是才提示不存在（现文案不动）。
- 打开那一段**必须走 `ExecutableGuard.Confirm`**。这是本项目第二次在"打开文件"上漏入口（第一次是拖入与收藏，见 CHANGELOG 0.2.1 修复段），新入口一旦自己 `Process.Start`，`warnOnExecutable` 就又不完整了。
- 自动补全**不跟着改**：`PathCompletion` 现在只出目录候选，把文件混进去会让挑目录时多滚十几行，收益抵不过噪音。输入认、补全不认。
- 打开后地址栏要**回滚成当前目录**（不是停在文件路径上），否则再按一次回车会重复执行上一次那个文件。
- `PathRules.Normalize` 的宽松写法（`D://work`、带尾随空格）对文件路径同样适用，不要另写一套。

**工作量**：约 **0.5 个工作日**（判据 + 回滚 + 中英文案 + 冒烟一次），无设置项、不动数据模型。

**暂缓原因**：不是缺陷——打不开就是打不开，用户不会误以为成功。而加它等于多开一条执行路径，得连带把补全、回滚、`warnOnExecutable` 的边界一起验。等 1.0 做"仅用键盘走完全程"那轮走查时一并定。

**开工前先定**：输入 `C:\x\` 这种以分隔符结尾、又恰好是某个文件的路径时算目录还是文件（现在的 `Normalize` 会保留尾分隔符，`File.Exists` 对带尾分隔符的文件路径返回 false，所以实际会落到"不存在"——要决定是接受这个行为，还是先 trim）。
