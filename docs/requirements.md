## 1. 项目概述

### 1.1 定位

一款**轻量、原生、启动即用**的 Windows 文件资源管理器，替代系统 Explorer 的日常文件浏览与整理场景。

不追求功能大而全，追求**打开快、不卡顿、不崩溃**。

### 1.2 核心矛盾与取舍原则

功能越多 → 启动加载越多 → 启动越慢。

因此确立**唯一最高优先级约束**：

> **任何功能，如果使冷启动时间增加超过 50ms，或引入无法兜底的崩溃点，则该功能不进当前版本。**

这条约束用于裁决所有功能取舍，优先级高于"用户要求"和"竞品都有"。

### 1.3 参考对象说明

需求描述中的 "Files" 指开源项目 **files-community/Files**。该项目技术栈为 WinUI 3 + .NET，实测冷启动约 **1.5–3.0 秒**。

**结论：参考其功能清单与交互，不参考其架构与技术基线。** 本项目选用 WPF 正是为规避该问题（理由见 §9.1）。

### 1.4 性能基线参考

| 产品 | 技术栈 | 冷启动（SSD 参考值） | 常驻内存 |
|---|---|---|---|
| Windows 11 资源管理器 | C++ / WinUI 混合 | 400–800ms（进程预热后 <300ms） | 80–150MB |
| files-community/Files | WinUI 3 + .NET | 1500–3000ms | 200–400MB |
| Everything | C++ / Win32 | <150ms | 20–40MB |
| **本项目** | C# / .NET 9 / WPF | **P50 ≤700ms，P95 ≤900ms（实测 578ms）** | **≤150MB（见 NF-05 分档，ADR-0002）** |

> 竞品数据为公开量级参考。本项目数值为 M0 同机实测，方法见 `docs/performance-gate.md`。

## 2. 术语

| 术语 | 说明 |
|---|---|
| 冷启动 | 进程创建 → 主窗口首帧可交互的耗时，不含系统文件缓存预热 |
| 虚拟化 | 仅渲染可视区域内的列表项，与项目总数解耦 |
| Shell | Windows 外壳组件，提供图标、右键菜单、属性页、预览等服务 |
| Known Folder | 系统已知文件夹（桌面/文档/下载等），由 `SHGetKnownFolderPath` 获取 |
| File ID | 卷内文件唯一标识（VolumeSerialNumber + FileIndex），重命名/移动后不变 |
| Preview Handler | Windows Shell 预览处理程序，COM 接口 `IPreviewHandler` |
| 性能预算 | 某功能允许消耗的启动耗时/内存额度，超出即降级 |
| STA 线程 | 单线程套间，COM 组件（含预览处理程序）必须在 STA 线程创建与调用 |

## 4. 设计原则

| 编号 | 原则 | 可验证的落地方式 |
|---|---|---|
| P1 | 首帧优先 | 窗口绘制完成前，禁止任何磁盘 IO、网络请求、Shell COM 调用、数据库打开 |
| P2 | 一切延迟 | 图标、缩略图、右键菜单、标签数据库、会话恢复、预览均在首帧后异步加载 |
| P3 | 单进程单窗口模型 | 不使用多进程架构，不做浏览器内核渲染 |
| P4 | 零常驻 | 无常驻后台服务、无开机自启、无托盘进程、无全盘文件监控 |
| P5 | 失败不崩溃 | 一切外部调用（Shell、磁盘、注册表、COM）必须有异常兜底与降级路径 |
| P6 | 可裁剪 | 功能模块独立初始化，未使用的模块不进入内存 |
| P7 | 不接管系统 | 不修改默认打开方式、不注入 Explorer、不改文件关联（D5） |

## 5. 性能与稳定性指标

> 本章是验收底线。任何功能验收前，这 11 项必须同时达标。

| 编号 | 指标 | 目标值 | 测量方法 |
|---|---|---|---|
| NF-01 | 冷启动 | 双口径：**用户感知**（`Process.Start` → 窗口出现并响应输入）P50 ≤900ms / P95 ≤1100ms，实测 694–769 / 776–883；**应用内埋点**（`App` 构造 → Loaded，门禁判定用）P50 ≤700ms / P95 ≤900ms，实测 511–569 / 540–619 | 见 `docs/performance-gate.md`；两轮 20 次 + 10 次；Release + ReadyToRun；埋点口径不含进程创建与 CLR 加载（约 190ms） |
| NF-02 | 热启动（退出后立即重启） | 与冷启动 P50 差异 ≤ 10%。不设独立绝对值——WPF 下两者共享同样的框架初始化成本，实测差异落在噪声内 | 同 NF-01 方法 |
| NF-03 | 打开含 10000 个项目的目录 | ≤800ms 显示首批内容，UI 线程无 >100ms 阻塞 | 构造测试目录 + 启动埋点 |
| NF-04 | 列表滚动帧率 | ≥55fps（10000 项目录） | `CompositionTarget.Rendering` 采样 |
| NF-05 | 常驻内存（10000 项目录，浏览 10 分钟） | **分档：** 单窗格 ≤150MB；双窗格 ≤185MB；开启预览窗格 ≤230MB。**口径：私有提交内存**（任务管理器"提交大小"列），不是含共享框架页的工作集。见 ADR-0002 | `tools/perf-fixture/Measure-List.ps1` 采集，取 GC 后稳定值 |
| NF-05R | 相对内存增量（Jianlan 私有提交 − 纯 WPF 空窗口私有提交） | 单窗格 10000 项滚动 ≤**65MB**（2026-11-05 实测 44.8MB，原 45MB 已无余量）；双窗格 ≤90MB（估算，开工前实测标定）。**代码回归判据**，不随框架底漂移；判定顺序为先 NF-05R 后 NF-05。见 ADR-0008 | 同上，加 `-Normalize`，空窗口 >90MB 时判不可判定 |
| NF-05H | 托管堆增量（滚动结束后 `GC.GetTotalMemory(true)`） | 单窗格 10000 项 ≤**12MB**。**降级判据**：环境处于高态、NF-05R 不可用时改看它，专门盯数据层，与框架底和两态无关 | 同上，探针输出 `managedHeapMb` |
| NF-06 | 稳定性（8 小时连续操作） | 0 崩溃、0 未处理异常；句柄增长 <10%，GDI 对象 <2000 | 脚本化压力测试 |
| NF-07 | 安装包体积 | ≤30MB（框架依赖）；自包含 ≤80MB | 发布产物 |
| NF-08 | 启动回归门禁 | **双层相对检测**：CI 超 baseline×2.5 失败（拦数量级退化）；本地发布前超 baseline×1.2 阻塞（拦渐进退化）。不做绝对耗时断言 | `baseline.json` + `tools/startup-bench`，规则见 `docs/performance-gate.md` §8 |
| NF-09 | 单次文件操作不得阻塞 UI | UI 线程阻塞 <16ms | 后台执行 + 进度反馈 |
| NF-10 | 长路径支持 | 支持 >260 字符路径（`\\?\` 前缀），不崩溃 | 构造 300 字符路径用例 |
| NF-11 | 错误提示友好 | 权限不足/文件占用/路径不存在等须给可理解提示，不弹原始异常 | 手工用例 |

**补充约束：**

- NF-12：预览窗格单次渲染超时 2s 必须降级显示"无法预览"，不得卡住 UI。
- NF-13：任何 COM 对象使用后必须释放，CI 中加入句柄/GDI 泄漏检测用例。

**性能约束：**
- 标签切换采用"按需加载 + 视图复用"：**非活动标签不保留文件列表**，切走时释放条目、
  切回时重新枚举（2026-11-07 落实，实测见 `performance-gate.md` §9.5.1）；
  路径、导航栈、选中项、滚动位置保留，不随内容一起丢。
- 单标签视图壳内存 ≤3MB；标签数上限 12（`SessionSettings.MaxTabs`），不做"超过 20 个时降级图标缓存"那套。

> **标签数为什么从 20 收到 12**（2026-11-05 修订，实测依据见 `docs/pane-refactor.md` §6.6）：
> ① 单标签最小宽 100 DIP，12 个 = 1200 DIP，1000px 窗口下已缩到最小宽、标题只剩两三个汉字；
> 20 个时窗口再窄一点就只能靠滚轮逐个找，翻页成本高于"关掉几个"的成本。
> ② 上限换个方式给用户也行——但每多一个标签就多一份保活的 `PaneViewModel`（导航栈、选中路径、
> 滚动锚点）。**2026-11-07 起条目不再计入这一项**（非活动标签释放内容，见 `performance-gate.md`
> §9.5.1），每个标签只剩几 KB 字符串状态，所以"内存"已不是收紧到 12 的理由；
> ①的宽度与可寻性才是。留此条仅为记录当时的依据，不要再用它推导 12 这个数。
> ③ 上限不是硬拦：到 12 个后 `Ctrl+T` 不再新建，用户可先关再开；`Ctrl+Shift+T` 的最近关闭列表独立
> 于 12 个上限，仍保留 10 条，所以"关错了还能捞回来"不受影响。

**与 FR-2.11 的区别：** 会话恢复是隐式、自动、单份；工作区是显式、命名、多份。设置中二选一，避免同时恢复导致标签重复。

#### FR-9.2 技术实现与性能约束（关键）

| ID | 要求 |
|---|---|
| FR-9.2.1 | 优先调用系统 Preview Handler（`IPreviewHandler`），失败时降级为内置简易渲染（文本/图片） |

## 9. 技术方案

### 9.1 技术栈（已确认）

**C# + .NET 9 + WPF，ReadyToRun 发布。**

选择理由：

| 维度 | WPF | WinUI 3 | Tauri | WinForms |
|---|---|---|---|---|
| 冷启动（实测基线） | ~600ms | 800–1500ms | 400–700ms | 100–200ms |
| Shell 互操作（图标/右键菜单/属性页/预览） | 成熟完善 | 一般，需 Win32 兜底 | 几乎为零，需 unsafe 绑定 | 成熟 |
| 列表虚拟化 | 内置 | 内置 | 需自建 | `VirtualMode` |
| 深色 + 高对比度 | 原生 | 原生 | 易（CSS） | 需全量自绘 |
| 失败模式 | 少见 | API 版本碎片化 | 易混淆 v1/v2，Rust 借用检查难修 | 少见 |

**核心判断：** 文件管理器约 90% 的工程难度集中在 Windows Shell 互操作，这恰好是 WPF 资料最厚、跨平台方案最薄的位置。选 WPF 的首要理由不是"快"，而是"能把稳定性做达标"——实测代价是启动基线高于 WinForms 约 350ms。

**不选 WinUI 3：** MUX 控件库初始化 + WinRT 激活导致冷启动基线 800ms 以上，且深色主题与 WPF 同样成熟但生态资料显著更少。参考对象 Files 启动慢正源于此。

**不选 WinForms：** 启动更快且虚拟化成熟，但深色模式与高对比度需全量自绘控件，工作量不亚于重写 UI 层，与 FR-5.1.1/FR-5.1.2 冲突。

**降级路径：** 若 M0 阶段 WPF 冷启动无法压到 600ms 以内，将"目录枚举 + 图标提取"两个热点用 C++ 写成独立 DLL 局部替换，不更换 UI 框架。

**环境准备（开发机当前缺少）：**
- 安装 .NET 9 SDK（约 200MB）
- Windows 10 SDK（调用 Shell 与 Win32 API 需要）
- Visual Studio 2022 或 Rider（可选，命令行 + AI 编码亦可）

### 9.3 目录枚举与列表性能

| ID | 要求 |
|---|---|
| T-01 | 枚举在后台线程执行，结果分批回调 UI（首批 ≤200 项立即渲染） |

| ID | 要求 |
|---|---|
| S-01 | 三重全局异常捕获（`AppDomain` / `Dispatcher` / `TaskScheduler`），写日志，UI 提示后可继续运行 |

## 11. 风险与对策

| 编号 | 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|---|
| R1 | 冷启动无法达标 | 核心目标失效 | 中 | M0 先验证；备选 Win32 宿主外壳混编，或热点改 C++ DLL |
| R2 | Shell 图标/右键菜单性能与稳定性 | 卡顿、崩溃 | 高 | 全异步 + 超时 + 缓存；右键菜单失败降级为自建精简菜单 |
| R3 | 预览窗格 Handler 崩溃或挂起 | 整个进程崩溃 | **高** | 独立 STA 线程 + 2s 超时 + 异常隔离；P2 阶段考虑独立进程渲染 |
| R4 | 双窗格 + 预览窗格内存超预算 | NF-05 超标 | 中 | 分档预算（150/185/230MB，ADR-0002）；超预算自动降级预览 |
| R5 | 彩色标签 File ID 跨卷失效 | 用户感知丢数据 | 高 | 文档明示限制；同卷内提供模糊重绑（FR-4.2.9） |
| R6 | 大目录（10 万项）性能崩坏 | 体验崩塌 | 中 | 分批枚举 + 简化模式 + 上限告警 |
| R7 | 长路径/权限/占用文件导致异常弹窗 | 稳定性差评 | 高 | S-02~S-04 全覆盖；错误提示统一封装 |
| R8 | 功能追加导致启动退化 | 目标逐步失守 | **高** | NF-08 双层相对门禁（CI 2.5×/本地 1.2×），对比 `baseline.json` 而非固定毫秒数 |
| R9 | 范围膨胀导致无法交付 | 项目停滞 | 高 | §8.3 黑名单硬性执行；新增需求须过 §1.2 裁决 |
| R10 | 开发者不熟悉 C#/WPF，AI 生成代码难以调试 | 效率下降 | 中 | 严格分层（Core 与 UI 解耦）、关键路径写单元测试、复用成熟开源实现参考 |

## 附录 B：功能-性能预算对照表

> 评审新功能时用此表判断。超出预算即需重新设计或砍掉。

| 功能 | 启动耗时预算 | 内存预算 | 超预算降级方案 |
|---|---|---|---|
| 主页卡片 | 0ms（首帧后异步填充） | 5MB | 减少卡片数量 |
| 标签页 | 5ms/标签 | 3MB/标签（视图壳） | 超出 20 个标签时禁用非活动标签图标缓存 |
| 双窗格 | 0ms（空骨架） | 30MB | 非焦点窗格简化渲染 |
| 彩色标签 | 0ms（延迟开库） | 8MB | 仅缓存可视区域标签 |
| 收藏书签 | 5ms（JSON 同步读，≤500 条） | 2MB | 降低上限或改为延迟加载 |
| 工作区 | 0ms（不参与冷启动） | 2MB | 恢复时逐个打开标签 |
| 预览窗格 | 0ms（默认关闭） | 40MB | 降级为纯文本 + 基本信息 |
| 界面字体与字号 | 0ms（系统字体，无需加载；列表枚举异步） | <2MB（字体元数据） | 字体枚举失败时仅保留默认字体 |
| 图标缓存 | 0ms（首帧后） | 25MB | 降低 LRU 容量 |
| 缩略图 | 0ms（滚动时暂停） | 20MB | 仅大图生成，其余用图标 |
| 历史记录 | 0ms（异步加载） | 5MB | 降低条数上限 |
| 右键菜单 | 0ms（按需构建） | 5MB | 降级为精简自建菜单 |
| 搜索过滤 | 0ms | 10MB | 限制过滤范围与结果数 |

**总预算核对（2026-11-03 实测 + ADR-0002 修订）：** 纯 WPF 空窗口实测 **81.0 MB**（框架固定成本），空目录 93.0 MB（自制部分 12.0 MB），10000 项目录滚动 110.7 MB（已优化，见 `performance-gate.md` §9.2.1）。

原 120 MB 档只给业务功能留 39 MB，M1 无法开工，故按 ADR-0002 上调为 **150 / 185 / 230 MB**，并新增相对增量门禁 NF-05R。新分档下可支配额度 69 MB。

NF-05R 初值 45 MB（当时实测 29.7 MB）；M1 批 3 完成后复测涨到 43–46 MB，45 已无余量、单轮即超标，故按 **ADR-0008** 于 2026-11-05 重新标定为 **65 MB**（双窗格 90 MB），并新增不随环境漂移的托管堆判据 NF-05H ≤ 12 MB。

**配套约束（上调阈值的前提，不实现则 150MB 无意义）：** 非活动标签页只保留路径与滚动位置、切回时重新枚举；右键菜单按需创建；预览解码设 `DecodePixelWidth` 且超预算自动关闭。
