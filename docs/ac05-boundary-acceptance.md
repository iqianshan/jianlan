## 3. 本轮发现并修复的缺陷

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 无权限目录显示为"空目录" | S3 首次实测 `items=0` 且无错误，界面与真正的空目录无法区分 | `FileSystemEnumerable` 的 `IgnoreInaccessible=true` 把根目录拒绝访问也吞掉了 | 枚举结果为 0 时用默认选项再探一次根目录，如实抛出 `UnauthorizedAccessException`（`DirectoryEnumerator.ThrowIfRootUnreadable`） |
| 错误提示直接外露英文异常 | 状态栏显示 `无法打开：Access to the path 'D:\ac05\noperm' is denied.` | `NavigateAsync` 把异常 `Message` 直接拼进状态栏 | 按错误码映射中文原因（没有权限 / 设备未就绪 / 路径过长 / 找不到此位置），原文只进 `app.log` |
| 打不开时地址栏不更新 | 导航失败后地址栏仍是上一个目录 | 失败分支只设置 `CurrentPath` 与面包屑，漏了 `AddressText` | 补上赋值 |

同时补齐两处诊断能力：

- `AppLog` 记录 `nav.open` 失败事件（`E1001`~`E1004`），符合 `docs/logging.md` §4；
- `perf-probe.json` 增加 `navigateError`，验收脚本据此区分"优雅失败"与"静默空表"。

截图证据：无权限目录、网络不可达两种场景的界面均为列表区"无法访问此文件夹" +
状态栏中文原因，无弹窗、无堆栈。

## 4. 未覆盖项（须在实体介质环境补测）

| 场景 | 模拟方式 | 没覆盖到什么 |
|---|---|---|
| 网络断开 | TEST-NET-1 保留地址，不可路由 | 已建立连接后链路中断（TCP 半开、SMB 重连） |
| U 盘热拔出 | `subst` 盘符挂载/撤销 | USB 驱动栈的延迟 I/O、`ERROR_NOT_READY`、真实句柄失效时序 |
| 只读介质 | ACL 只读目录 | 卷级只读（`ERROR_WRITE_PROTECT`）；本机无光驱，非管理员无法挂载只读 VHD |

脚本可直接复用，换真实介质后只需改场景路径。

## 5. 遗留问题

1. **`E7001`（全局热键注册失败）未在 `logging.md` §4 登记**。探针与已有实例并存时必然出现
   （`err=1409`），需补文档，或让探针模式跳过热键注册。
2. **探针模式仍注册全局热键**：诊断进程不该抢占用户的 `Ctrl+,`。
3. **UNC 面包屑丢失前缀**：`\\192.0.2.1\share` 显示为 `192.0.2.1\share`（`Breadcrumb` 的
   Label 不含 `\\`，导航目标正确）。与资源管理器的"网络 > 服务器 > 共享"不一致，属体验问题。
4. **S1 工作集 172 MB**：滚动场景下超出 NF-05 的 150 MB 档，与上一轮 publish 内存超标同一议题。
5. **`window_drive.py screenshot` 在窗口较高时裁掉底部**（DIB 高度与 DPI 不匹配）。本轮已改用
   探针 `statusText` 取证；工具本身待修，否则 AC-06 视觉走查会漏掉状态栏。

## 6. 复测周期

边界逻辑改动（枚举、导航、监听、文件操作）或发布前必须重跑；纯 UI 改动可只跑 S1/S3/S5b。
