# 环境对照工具

判断"启动变慢"是 Jianlan 的代码回归，还是整台机器的状态问题。

## 为什么需要它

2026-11-03 实测：同一份二进制、同一台机器，40 分钟内测出两组相差一倍的启动耗时
（511 ms 与 1102 ms）。当时 CPU 32%、内存 48%、CPU 超频、磁盘空闲，所有常见环境指标
都正常——如果只看 Jianlan 的数字，会判定为严重回归，然后去改本来没问题的代码。

真相是整机 WPF 都慢了一倍。跑这个空窗口（10 行代码，无业务逻辑）就立刻能看出来。

## 用法

```bash
# 编译并测 10 次
pwsh tools/env-check/Measure-Baseline.ps1 -Runs 10

# 已编译过，只测
pwsh tools/env-check/Measure-Baseline.ps1 -Runs 10 -SkipBuild
```

## 判据

| 空窗口 P50 | 含义 | 该做什么 |
|---|---|---|
| ≤ 800 ms | 环境正常（本机正常值 485–665 ms） | Jianlan 超标即为代码问题 |
| > 800 ms | 环境异常 | 重启、关闭驻留程序后重测；不要动代码 |

## 手工判定

`Measure-Startup.ps1` 在"判定未通过、但离散度正常"时，会自动提示先跑这个对照——
因为"数据很稳、但整体偏移"正是环境变慢的典型特征，也是最容易误判成代码回归的情况。

详见 `docs/performance-gate.md` §11。
